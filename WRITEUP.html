2. Starting Point

  • Starting Point: Built from scratch as an editor-native TrueForge extension for Visual Studio Code.
  • Design Rationale: Rather than inheriting the legacy baggage of existing open-source coding tools (Cline, Continue, Roo Code) that bind prompt loops to proprietary backends, Forge Agent was engineered from inception around TrueForge as the single orchestration harness.
  • Harness: Runs against @truefoundry/trueforge@latest locally on port 8790. MIT license preserved.
  • Repository: Public at https://github.com/anxj-xe/forge-agent.git.

3. Architecture on TrueForge

  • Client Layer (VS Code Extension): Manages user interactions: Inline Edit (Ctrl+K), Sidebar Webview, and CodeLens reviews. Embedded within the extension is an HTTP MCP Bridge server on http://127.0.0.1:8792 exposing core tools: read_file, search_workspace, propose_edit, and run_terminal_command.
  • Harness Layer (TrueForge on port 8790): The client creates sessions via POST /api/v1/sessions and sends turns via POST /api/v1/sessions/:id/turns. Real-time token streaming is ingested over Server-Sent Events (SSE). Immediate cancellation is driven via POST /api/v1/sessions/:id/turns/:turnId/cancel.
  • Harness Features Utilized:
    • Context Compaction (compaction: { enabled: true }): Compresses conversational trajectory to prevent context overflow.
    • Large Tool Response Truncation (large_tool_response: { enabled: true }): Protects against oversized workspace file scans.
    • Dynamic Subagents: Enabled in agent manifest for modular task delegation.

4. How Context is Selected

Context selection is governed by ContextEngine operating under a strict 16 KB size budget:

  • Explicit Mentions: Resolves @file:<path> and @symbol:<name> tags. For symbols, it queries VS Code's Workspace Symbol Provider to extract only the enclosing function/class definition rather than loading entire files.
  • Autonomous Relevance Ranking: For unprompted multi-file requests (Task B), the engine extracts high-signal keywords from the prompt and computes a relevance score across workspace paths and contents in src/, tests/, and docs/. Top candidates are truncated to fit within the budget.
  • Transparency: Every assembled context displays a real-time summary log in the UI (e.g. Budget: 16 KB | Used: 11 KB | Files: 3), logging which files were selected and the rationale.

5. Model Setup

  • Primary Model: google-gemini/gemini-3-5-flash-lite (configured in TrueForge model catalog).
  • Fallback Model: google-gemini/gemini-3-5-flash (configured in TrueForge model catalog).
  • Hosting & Costs: Served via Google AI Studio through TrueForge's local harness; approximate cost is $0.00 (under free tier).
  • Model Switching & Resilience: Users can switch models in the TrueForge Settings UI or update agents/forge-coding-agent.json. The extension's ResilienceManager automatically falls back to forge-coding-agent-fallback upon connection timeout, unreachable host, or authentication error, requiring zero user action.

7. Tools Used

  • Core Stack: TypeScript 5.4, Node.js 20+, VS Code Extension API (^1.85.0), esbuild.
  • Frameworks & Libraries: @truefoundry/trueforge agent harness, diff (jsdiff) for structured patching.
  • AI Assistants: Google Antigravity & Gemini CLI used during development (declared per competition rules; costs no points).

8. Known Limitations & Future Work

  • Limitations: The MCP Bridge operates over local HTTP port (8792); concurrent external applications using the port can cause brief port-shift overhead. Context ranking uses lexical frequency rather than dense embeddings due to local compute bounds.
  • What We Would Build With Another Month:
    1. Native stdio MCP Transport: Switch MCP Bridge to stdio communication to eliminate network port bindings entirely.
    2. Tree-Sitter Semantic Call Graphs: Integrate Tree-Sitter AST parsing to trace symbol dependencies across imports automatically.
    3. Interactive Multi-Turn Diff Refinement: Allow users to highlight specific hunks and submit natural-language follow-ups prior to acceptance.
